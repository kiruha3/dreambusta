# DreamBusta

Самостоятельная библиотека на **Vue 3 + TypeScript + Vite**, с отдельным Node API и SQLite. Оформление взято из TechHelper; читалка и импорт книг — из WBook. Код исходного WBook сохранён в коммите `b5fb240`; его личная библиотека не переносилась.

## Запуск

Требуется **Node.js 24+**. Из этой папки:

```powershell
npm ci
npm run dev
```

- Интерфейс: http://localhost:5173/library
- API: http://localhost:5176/api/session
- Первый редактор: http://localhost:5173/login — задайте собственные email и пароль от 12 символов. Создание первого редактора разрешено только с локального компьютера. Предустановленных учётных записей нет.
- Для телефона используйте IP компьютера и порт 5173. Интерфейс запускается с `--host 0.0.0.0`, управление требует входа.

На этом компьютере Node 24 также доступен в комплекте Codex. При системном Node 22 запускайте так:

```powershell
& "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe" scripts/dev.mjs
```

Рабочая библиотека начинается пустой. Тесты создают временные базы и не добавляют свои материалы или редактора в рабочую `data/`.

## Что работает

- Каталог с поиском по названию, автору, описанию и тегам, фильтрами и сортировкой.
- Карточка: название, автор, описание, теги, обложка, видимость, кнопка скачивания оригинала.
- Подборки с повторным использованием материалов; порядок меняется перетаскиванием и стрелками.
- Читаемые адреса `/library/nazvanie` и `/collections/podborka`. Внутренние ID отделены от адреса. Переименование названия не меняет URL; смена адреса сохраняет прежние ссылки за тем же материалом. После удаления адрес не переиспользуется.
- Файлы загружаются потоком на диск; большие видео не загружаются целиком в память. Воспроизведение поддерживает HTTP Range.
- Оформленная статья, обычный «Текст» и отдельная читалка «WBook» (прежнее название вкладки — «Скорочтение»). Клик по слову меняет позицию, текущее слово подсвечивается, контекст следует за чтением. Есть жест удержания и изменения скорости, пробел/стрелки, поиск и настройка шрифта. Большие книги показываются частями без создания DOM для всего текста.
- В WBook галочка «Читать по главам» ограничивает контекст текущим разделом. Оглавление с поиском, предыдущая/следующая глава и остановка в конце главы сохраняют глобальную позицию слова. По умолчанию используется родное оглавление EPUB, затем поиск коротких заголовков. В настройках можно задать буквальное начало заголовка, просмотреть результат и применить; «Убрать разбивку» возвращает полный текст и сбрасывает своё правило. Настройки сохраняются в текущем браузере отдельно для каждой версии материала.
- Прогресс, скорость, последний режим и избранное сохраняются в текущем браузере. Для новой текстовой версии используется отдельный ключ прогресса.
- PDF и слайды сохраняют собственную страницу и масштаб при переключении режимов и повторном открытии. Новая версия начинает отдельный прогресс. У презентаций есть миниатюры, переход по номеру, масштаб и полный экран.
- Повторное добавление той же ссылки или файла с тем же SHA-256 получает сообщение о существующей карточке. Для обновления используется её действие «Загрузить новую версию» или «Обновить из источника».
- PDF.js показывает PDF непрерывной вертикальной лентой. Кнопка «Страницы» открывает/скрывает левую панель, по умолчанию закрытую. В панели переключаются «Список» и «Миниатюры»; изменение вида сохраняет страницу и масштаб. Миниатюры рисуются только вблизи видимой области. Word открывается через readOnly-компонент TechHelper, статические слайды — через парсер DreamAgent Desktop.
- Светлая/тёмная тема, интерфейс на мобильной ширине.
- Вход редактора, HttpOnly session cookie, CSRF и Origin, скрытые файлы защищены теми же правами, что и карточки. Настройка закрытого каталога.

## Форматы и ограничения

| Материал | Доступные режимы | Лимит файла |
|---|---|---|
| MD / Markdown | Статья, текст, скорочтение | 25 МБ |
| TXT, EPUB, FB2, FB2.ZIP, MOBI, AZW3 без DRM | Текст, скорочтение | 25 МБ |
| PDF | Страницы; текст и скорочтение при наличии текстового слоя | 100 МБ |
| DOCX | Документ, текст и скорочтение при наличии текста | 100 МБ |
| DOC | Преобразование в DOCX установленным LibreOffice | 100 МБ |
| PPTX | Статические слайды; текст и скорочтение при наличии текста | 32 МБ |
| MP4, WebM, MOV, M4V | Видеоплеер, при поддерживаемом браузером кодеке | 1 ГБ |
| MP3, M4A, OGG, WAV, FLAC | Аудиоплеер, при поддерживаемом браузером кодеке | 1 ГБ |

Общий извлечённый текст ограничен 50 МБ в UTF-8. Архивы имеют дополнительные ограничения распаковки. HTML-уроки из ZIP не импортируются; FB2.ZIP остаётся книжным форматом.

PDF без текста и DOCX без текста не отбрасываются: их можно просмотреть. OCR и автоматическая расшифровка не выполняются. Готовую расшифровку видео/аудио редактор может добавить в карточке — появятся статья, текст и скорочтение.

Кодеки PDF.js (включая JPEG2000), карты символов и стандартные шрифты выдаются локально из `/pdfjs/<версия>/` и включаются в production build. Версия ресурсов совпадает с движком; обращений к стороннему CDN нет. Стили PDF изолированы внутри просмотрщика.

**DOC:** LibreOffice на данном компьютере отсутствует. Оригинал сохраняется с понятной ошибкой; после установки конвертера загрузите новую версию. Можно сразу загрузить DOCX. Переменная `LIBREOFFICE_PATH` указывает полный путь к `soffice`/`soffice.exe`. Преобразование имеет отдельный профиль и тайм-аут 90 секунд.

**PPTX:** используется статический рендер поддержанных фигур, текста и изображений. Анимация, диаграммы, SmartArt, встроенное видео, сложная вёрстка/шрифты могут отличаться от PowerPoint. Внешние связи в пакете отклоняются. Для точного визуального соответствия можно загрузить экспортированный PDF. Конвертация PPTX через LibreOffice здесь не включена.

Пустая настройка обводки не рисует рамку вокруг текста. Отдельные фрагменты сохраняют цвет, размер, начертание и подчёркивание; при отсутствии исходного шрифта используется Arial/sans-serif. Скруглённые прямоугольники сохраняют форму, а неподдержанные тени не заменяют всю плашку заглушкой. Эффекты и сложные фигуры по-прежнему могут отображаться упрощённо.

Нативные таблицы PPTX отображают ячейки, объединения, заданные в файле границы, заливки и форматирование текста. Текст таблиц читается по строкам в режимах «Текст» и «WBook». Автоматические стили таблиц из темы PowerPoint пока не воспроизводятся полностью.

Векторные иконки с числовыми координатами DrawingML (линии, кривые Безье, замкнутые контуры) и круглые радиальные градиенты с прозрачностью отображаются в SVG. Формулы геометрии и остальные неподдержанные формы сохраняют предупреждение о неполном отображении.

**Word:** это просмотрщик существующего TechHelper, без функций редактирования и без отдельной плашки «редактирование недоступно». Сложная вёрстка может отличаться от Microsoft Word. Модуль загружается отдельно от каталога (крупный lazy chunk).

## Ссылки и сохранённые публикации

Поддержаны отдельные видео YouTube, Rutube и VK, прямые URL медиафайлов, публичные адреса TechHelper `/shared/d/...`, `/shared/...`, `/shared/kb/...`, а также Buildin `/share/...`. Неизвестный источник получает понятное сообщение, а не универсальный iframe.

Плеер внешнего видео загружается сразу при открытии материала, без промежуточной кнопки. Воспроизведение запускается пользователем в плеере. Встраивание, региональные ограничения, авторизация источника и кодек могут мешать воспроизведению; есть переход к источнику. Настоящее воспроизведение каждого провайдера требует проверки на конкретных ссылках. Наличие записи в каталоге не обещает офлайн-доступ к потоку.

Публикации сохраняют полученные HTML/текст и доступные растровые изображения. PDF TechHelper запрашивается только как **опубликованный preview**, без `variant=original`, закрытых исходников, чужих сессий и паролей. JSON документов/статей преобразуется в статью, сохраняющую базовые заголовки, списки, таблицы и опубликованный текст. Полная эквивалентность всех редакторов TechHelper не заявляется.

В публикациях TechHelper `/shared/kb/...` сохраняется основная статья и дерево опубликованных подстатей (до 100 страниц и 100 МБ на публикацию с ресурсами). Ссылки `kb://...` открывают сохранённые разделы внутри библиотеки, например `?page=01-baza-znaniy`; есть выбор раздела и возврат к основной статье. Ссылки на заголовки прокручивают статью, внешние ссылки ведут к источнику. Адрес раздела сохраняется при переименовании и не передаётся другой странице после удаления. Каждый раздел имеет отдельное место чтения. Обычные переходы не обращаются к TechHelper; дерево обновляется только вручную и целиком, при ошибке сохраняется предыдущая версия со всеми разделами.

Buildin использует проверенный анонимный web API `api/docs/<share-id>`. По умолчанию сохраняется выбранная статья со всеми подстраницами, в том числе под обычными блоками. Соседние статьи не включаются. Сложные блоки могут сохраняться в текстовом представлении; приватный API и логин не используются. Контракт внешнего web API может измениться.

При импорте TechHelper и Buildin доступны три варианта: **только статья**, **статья и подстраницы** (по умолчанию), **всё публичное меню**. В последнем варианте сначала показывается дерево с галочками: можно исключить отдельные страницы, исходная статья остаётся обязательной. Выбор сохраняется и повторяется при обновлении. Режим ветки подхватывает новые подстраницы; ручной выбор меню сохраняет только отмеченные адреса. Ограничение — 100 страниц / 100 МБ вместе с ресурсами.

Справа в просмотрщике отображается раскрывающееся дерево сохранённых страниц с текущим разделом; на телефоне оно сворачивается кнопкой «Страницы публикации». Режимы «Статья», «Текст» и «WBook» остаются отдельными. Кнопка редактора **«Обновить ветку»** обновляет весь сохранённый набор одной операцией. Обычное чтение и переходы используют локальную копию.

Открытие сохранённой статьи **не обращается к источнику**. В карточке показывается дата сохранения. Обновление запускает редактор:

1. Кнопка «Обновить ветку» в просмотрщике (или обновление в редакторе).
2. При успехе сохраняется новое представление.
3. При закрытии/удалении источника старая версия остаётся доступна. Можно оставить её или явно завершить обновление с потерей доступа.
4. Сетевая ошибка и тайм-аут не стирают последнюю рабочую версию.

Обновление атомарно: если не удалось получить опубликованный PDF или изображение, сохраняется вся предыдущая публикация. Одновременное изменение карточки, замена файла или явное завершение обновления отменяют устаревший результат с сообщением о конфликте; повторите действие из актуальной карточки.

По умолчанию импорт принимает публичные HTTP(S) адреса. Он не передаёт логин/пароль или cookies пользователя. DNS-адрес закрепляется на запрос; перенаправления проверяются заново, проверка TLS остаётся включённой. HTML очищается; ресурсы ограничены по размеру и типу.

Для корпоративного TechHelper во внутренней сети оператор может создать `data/trusted-source-origins.json`:

```json
["https://tracker.slsoft.ru"]
```

После изменения перезапустите API. Это точные HTTPS origin с DNS-именами, без путей, wildcard и нестандартных портов. Разрешение относится только к перечисленным серверам и их ресурсам; другие внутренние адреса остаются запрещены. Loopback, link-local и адреса служб метаданных запрещены и для доверенных источников. Список не изменяется через редактор API и не хранится в Git. На текущем компьютере `tracker.slsoft.ru` разрешается в корпоративный адрес и добавлен в этот локальный список.

## Хранение и перенос

`data/` игнорируется Git. Внутри:

- `library.sqlite`, `-wal`, `-shm`: метаданные, адреса и история slug, подборки, настройки, хеши паролей и сессии;
- `files/`: исходники и производные файлы;
- `snapshots/`: опубликованные ресурсы;
- `covers/`: обложки.

Vite запрещает прямую выдачу хранилища, включая `/@fs/`. Не размещайте `DATA_DIR` внутри `public/` или `dist/` и не задавайте корень проекта либо его родителя: приложение проверяет эту настройку при запуске. Пользовательские файлы доступны через API с проверкой прав.

Резервная копия: остановите API и скопируйте **весь каталог data/**. Для восстановления положите его рядом с исходниками либо задайте `DATA_DIR`. Не копируйте живую SQLite только одним файлом без WAL. Скопированная база включает активные сессии; для их сброса удалите строки таблицы `sessions` локальной SQLite-командой.

Смена версии сохраняет materialId, адрес, описание, обложку и место в подборках. Если обработка новой версии не удалась, старая остаётся активной. Удаление карточки закрывает API-доступ к файлам и убирает материал из подборок; отдельного сборщика оставшихся файлов и UI истории старых версий пока нет. Дисковые копии не следует считать корзиной с гарантированным восстановлением.

Исходная библиотека `E:/WBook/app/.wrangler/state` не менялась. Старые D1/R2/React-файлы сохранены как исторический код и не участвуют в Vue-сборке. Миграция их данных, SHA-адресов и localStorage не запускалась.

## Переменные сервера

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATA_DIR` | `data` | Каталог библиотеки |
| `API_PORT` | `5176` | Порт API и цель Vite proxy |
| `API_HOST` | `0.0.0.0` | Адрес API |
| `WEB_PORT` | `5173` | Порт Vite dev |
| `SECURE_COOKIE` | выключено локально | `1` для HTTPS-размещения |
| `LIBREOFFICE_PATH` | стандартный путь / `soffice` | Конвертер старого DOC |
| `DREAMBUSTA_AI` | `on` | `off` отключает модели, оставляя полнотекстовый поиск |
| `DREAMBUSTA_OLLAMA_URL` | `http://127.0.0.1:11434` | Локальный Ollama; разрешены только loopback HTTP-адреса |
| `DREAMBUSTA_EMBED_MODEL` | `embeddinggemma:latest` | Локальная модель векторов |
| `DREAMBUSTA_ANSWER_MODEL` | `gemma4:e2b` | Локальная модель ответа по найденным источникам |

Для локальной проверки сборки: в одном терминале `npm run api`, в другом `npm run build` и `npm run preview`. Для самостоятельного сервера используется HTTPS reverse proxy, выдающий `dist/` с SPA fallback и `/api` к Node API.

## Проверки

### Поиск по текстам и ответы по источникам

Общий поиск открывается кнопкой «Поиск» или `Ctrl+K` / `Cmd+K`. Он ищет по
названиям, метаданным и извлечённому содержимому всех доступных материалов,
включая вложенные страницы публикаций и добавленные расшифровки. Есть фильтры
типа, текущего материала и подборки. Выдача содержит цитату и переход к абзацу,
странице PDF, слайду или вложенной странице. Старая ссылка с другой версией
текста показывает сообщение об обновлении материала.

Поиск полностью принадлежит DreamBusta: SQLite FTS5, сохранённые векторы,
разбиение, очередь, ранжирование и RAG находятся в `server/search/`. Сервисы,
ключи и индексы Теххелпера не используются. Из ТХ перенесены подход к разбиению
и объединению рангов (RRF), проверка актуальности источников и взаимодействие
окна поиска. Векторный поиск выполняет точное сравнение в SQLite/Node, без
приближённого индекса и отдельной векторной БД.

Для моделей нужен установленный **локально на том же компьютере/сервере**
Ollama. Один раз загрузить модели, затем запустить runtime:

```sh
ollama pull embeddinggemma
ollama pull gemma4:e2b
ollama serve
```

На текущем рабочем компьютере обе модели уже установлены. Браузер общается
только с API DreamBusta; тексты не отправляются в ТХ или облачную модель.
Индекс и векторы хранятся в той же приватной `library.sqlite` и строятся
автоматически после запуска/изменений. Библиотека доступна во время подготовки
эмбеддингов; при отказе runtime остаётся поиск по словам. Очередь обрабатывает
по 8 фрагментов, откладывает неудачный вход и продолжает остальные; отказ
runtime повторяется через минуту. Для существующих PDF привязка к страницам
восстанавливается из сохранённого оригинала только при совпадении текста.
Короткие абзацы объединяются в блоки до 1200 символов с отдельными позициями
абзацев; границы глав, PDF-страниц, слайдов и страниц публикаций сохраняются.
Длинные абзацы разбиваются с перекрытием. Векторы сохраняются как Float32;
старые JSON-векторы тоже читаются. Неизменённая библиотека повторно не
разбирается между запросами и порциями индексации; внешние изменения SQLite
отслеживаются отдельно.

«Спросить по найденному» использует до 6 актуальных текстовых фрагментов.
Модель возвращает структурированные утверждения с номерами источников;
сервер проверяет ссылки и повторно проверяет доступ/версию перед выдачей.
Если источник изменился, текста недостаточно или модель недоступна, интерфейс
сообщает об этом. Метаданные без текста не выдаются за основание ответа.
Сканы без OCR и медиа без расшифровки ищутся только по метаданным.

`GET /api/search?q=...` поддерживает `kind`, `collection`, `material`, `limit`
(1–50) и `offset`; `POST /api/search/answer` принимает те же параметры и
`query`. Это чтение, доступное читателю открытой библиотеки; закрытая требует
входа, скрытые материалы доступны только редактору. Для генерации действуют
ограничения частоты и числа одновременных запросов.

`npm run test:e2e` запускает обычные и поисковые сценарии во временных
библиотеках с тестовым loopback runtime. Отдельно `npm run test:search:live`
проверяет настоящие локальные эмбеддинги, поиск с переформулировкой и ответ со
ссылкой; рабочая библиотека не используется. Артефакты — `.superpowers/search/`.

```powershell
npm test
npm run typecheck
npm run build
npx playwright install chromium
npm run test:e2e
node --experimental-strip-types tests/live-sources.mjs
```

Unit/HTTP тесты проверяют импортёры, slug/исторические адреса, SQLite, доступ/CSRF, оригиналы и Range, share-снимки и отказы обновления, конфликты операций, дубли и защиту сетевых запросов. Отдельный HTTP-тест проверяет запрет базы/WAL/исходников через Vite. Browser E2E использует временную библиотеку: создание редактора, MD, карточка/ссылка, чтение/позиция, подборка, PDF-скан, страницы PDF при смене режима/версии, readOnly Word с таблицей, порядок PPTX, 20 плотных слайдов на телефоне с масштабом/миниатюрами/полным экраном, большая книга, WAV, мобильный экран и тёмная тема. Отдельная сетевая проверка читает присланную публичную статью Buildin. Артефакты — в игнорируемой `.superpowers/e2e/`.

## Временный отдельный Git

Вложенный репозиторий находится в этой папке. Базовый коммит `b5fb240`, ветка разработки `feat/vue-library`, remote не подключён. Пока он существует, не добавляйте папку в родительский Git как submodule.

Когда будете переносить в основной репозиторий: сначала сохраните нужную историю/резервную копию, затем удалите **только `dreambusta/.git`**, после чего добавьте исходники из родительского репозитория. `data/`, `.env*`, `node_modules/`, сборки и тестовые артефакты должны остаться исключёнными.
