# WBook на VPS

Сервер пользователя: `45.9.12.136`, Ubuntu 22.04. Внешний адрес — [https://wbook.45-9-12-136.sslip.io/](https://wbook.45-9-12-136.sslip.io/). Размещение на этом VPS и бесплатный адрес разрешены пользователем 2026-11-10.

Nginx принимает HTTPS на порту 443 и передаёт запросы приложению на `127.0.0.1:8787`. Обращения к домену по HTTP перенаправляются на HTTPS. Прямой адрес `http://45.9.12.136/` также доступен. Служба `wbook` запускает собранный Worker в локальном runtime Wrangler от отдельного системного пользователя `wbook`. Для работы библиотеки не требуется аккаунт Cloudflare.

Бесплатный поддомен сервиса [sslip.io](https://sslip.io/) содержит IP сервера и автоматически разрешается в него. При смене IP потребуется новый адрес и сертификат. Собственный зарегистрированный домен не используется.

## Расположение файлов

| Путь | Назначение |
|---|---|
| `/opt/wbook/releases/` | Исходники, зависимости и сборки по версиям |
| `/opt/wbook/current` | Ссылка на работающую версию |
| `/var/lib/wbook/storage` | База каталога и файлы книг; сохранять при обновлении |
| `/var/lib/wbook/runtime` | Служебные файлы runtime |
| `/etc/systemd/system/wbook.service` | Служба приложения, образец — `wbook.service` |
| `/etc/nginx/sites-available/wbook` | Настройки Nginx, образец — `nginx.conf` |
| `/etc/letsencrypt/live/wbook/` | Сертификат Let's Encrypt и закрытый ключ; не добавлять в Git |
| `/etc/letsencrypt/renewal-hooks/deploy/wbook-reload-nginx` | Перезагрузка Nginx после продления сертификата, образец — `reload-nginx.sh` |

Локальная библиотека на компьютере остаётся в `E:\WBook\app\.wrangler\state`. Копирование исходников на VPS не переносит книги и прогресс чтения.

## Проверка и управление

После подключения к серверу по SSH:

```bash
systemctl status wbook nginx --no-pager
journalctl -u wbook -n 80 --no-pager
curl --fail http://127.0.0.1:8787/api/books
```

Перезапуск приложения:

```bash
systemctl restart wbook
```

Проверка и применение изменённых настроек Nginx:

```bash
nginx -t && systemctl reload nginx
```

Обе службы должны быть включены в автозагрузку через `systemctl enable wbook nginx`.

## HTTPS

Сертификат Let's Encrypt выпущен через Certbot с проверкой HTTP-01. Каталог проверки — `/var/www/wbook-acme`; Nginx обслуживает его по пути `/.well-known/acme-challenge/`. Этот путь по HTTP нужен и при последующих продлениях.

Автоматическое продление выполняет `certbot.timer`. После продления исполняемый hook `wbook-reload-nginx` проверяет конфигурацию и перезагружает Nginx. Для проверки:

```bash
systemctl list-timers certbot.timer --no-pager
certbot renew --cert-name wbook --dry-run --non-interactive --no-random-sleep-on-renew
```

При восстановлении на новом сервере сначала включите HTTP и каталог проверки, выпустите сертификат для фактического домена, затем подключайте HTTPS-блок из `nginx.conf`. Без файлов сертификата Nginx не запустится с этим блоком.

## Обновление

Распакуйте новую версию в отдельную папку внутри `/opt/wbook/releases`, назначьте владельца `wbook:wbook`, установите зависимости через `npm ci` и выполните `npm run build` от пользователя `wbook`. Служба использует Node.js из `/usr/local/bin/node`; на сервере установлен Node.js 22.20.0.

После успешной сборки переключите `/opt/wbook/current` на новую папку и перезапустите `wbook`. При обновлении сохраняйте `/var/lib/wbook/storage`; повторное исполнение начальной SQL-схемы для существующей базы не требуется. Если обновление не запускается, верните ссылку на предыдущую версию и снова перезапустите службу.

Для резервного копирования остановите `wbook`, скопируйте всю папку `/var/lib/wbook/storage`, затем запустите службу. Прогресс чтения хранится в браузере устройства и в эту копию не входит.
