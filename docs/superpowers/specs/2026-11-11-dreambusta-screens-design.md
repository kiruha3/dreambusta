# DreamBusta — экраны и состав реализации

Дата: 11 ноября 2026 года. Версия макетов: 1.

Это предложение интерфейса на основе [требований библиотеки](2026-11-11-dreambusta-library-design.md). Пользователь запросил изображения экранов перед реализацией. Код приложения, API, зависимости и размещение в этой работе не меняются. Все названия материалов, обложки, сроки и числа на макетах — демонстрационные данные.

## Принятые для макетов решения

Общая библиотека имеет каталог и подборки. Тип материала выбирается фильтром каталога, поэтому книги, документы, презентации, видео и аудио не получают пять отдельных дублирующих разделов. У материала один постоянный адрес и единая рамка просмотра; набор режимов определяется доступными представлениями.

Рассмотрены три подхода: отдельное приложение для каждого формата; каталог с открытием всего во внешних приложениях; общий каталог с собственными просмотрщиками и адаптерами источников. Предложен третий: он сохраняет выбор способа чтения и позволяет использовать одни материалы в нескольких продуктах. Внешний переход остаётся явным запасным действием, если встроенный просмотр недоступен. Это решение автора макетов для рассмотрения пользователем.

Управление вынесено отдельно и доступно редактору после входа. Читатель не видит загрузку, таблицу обработки и настройки источников. Открытость каталога ещё не выбрана: макеты показывают пользователя с доступом к чтению. Экран входа иллюстрирует отдельную авторизацию редактора; способ авторизации при реализации предстоит выбрать. Наличие этого экрана не закрепляет общий вход с другими продуктами.

За основу оформления взяты реальные токены TechHelper: белый фон, основной цвет #27272a, спокойные серые поверхности, границы #e4e4e7, радиус 0.65rem, Geist с кириллицей. Цвет используется в обложках и состояниях. В макеты копируются только локальные шрифты; функции TechHelper не подключаются. На мобильных устройствах боковое меню заменяется компактной навигацией, инструменты чтения остаются доступными.

Уточнения пользователя во время отрисовки: share-материалы хранят полученную публикацию и открываются без запроса при каждом чтении; обновление вручную с предупреждением о недоступности. Добавлены публичные страницы Buildin и ссылки DreamBusta без GUID. Предлагаемые адреса: /library/reglament-soglasovaniya и /collections/start-v-dreamdocs; старые slug перенаправляются после явного переименования адреса.

Фильтр «Документы» включает PDF, Word, MD и share-статьи. «Статья» — пользовательская подпись текстового документа, «Подкаст» — аудиоматериала, а не дополнительная несовместимая модель.

## Карта экранов

~~~text
Библиотека
├── Каталог → фильтры типов, поиск по метаданным → Материал
├── Подборки → Подборка → тот же Материал
└── Материал
    ├── PDF → PDF / Текст / Скорочтение
    ├── DOCX и подготовленный DOC → Документ / Текст / Скорочтение
    ├── Markdown → Статья / Текст / Скорочтение
    ├── Книга или TXT → Текст / Скорочтение
    ├── PPTX → Слайды / Текст / Скорочтение
    ├── Видео → плеер / опубликованная расшифровка, если есть
    ├── Подкаст → плеер / опубликованная расшифровка, если есть
    └── Share TechHelper → разрешённая статья / документ / запись

Управление (после входа редактора)
├── Материалы → Добавить: Файл / Ссылка
│             → Карточка и версии → Видимость
├── Подборки → состав / порядок / видимость
└── Источники → разрешённые подключения / возможности подготовки
~~~

## Что предстоит реализовать

| Блок | Работа | Основа и проверяемый результат |
|---|---|---|
| Общая оболочка | Навигация, тема, мобильное меню, состояния загрузки и ошибок | Токены TechHelper; навигация не зависит от LMS |
| Каталог | Общая модель материала, метаданные, поиск, фильтры, пагинация | Расширение WBook; поиск первой версии по метаданным |
| Подборки | Связи с существующими материалами, порядок, обложка и видимость | Удаление связи не удаляет материал; повторное использование без дубликатов |
| Получение файлов | Авторизованная загрузка, лимиты по типам, сохранение оригиналов и версий, состояния обработки | API и хранилище потребуют адаптации; крупное медиа не проходит целиком через память процесса |
| Текст и книги | Сохранить импортёры WBook; добавить MD, DOC-конверсию и расширяемый реестр | MD, TXT, Word, существующие книжные форматы; понятные ошибки |
| Оформленный просмотр | PDF.js и DOCX readOnly; Markdown-рендеринг | Адаптация TechHelper к React, проверка DOCX-библиотеки с React 19 |
| Презентации | PPTX → PDF и текст по порядку слайдов; миниатюры и режимы | Конвертер TechHelper; подходящие части парсера Desktop; без анимации и редактирования |
| Читалка | Сохранить жесты/клавиатуру WBook, отдельные позиции режимов и версии текста | Точное соответствие странице/слову только при наличии карты, иначе отдельные позиции |
| Share-ссылки | Адаптер публичных API документов/БЗ/записей, сохранение полученной публикации и ресурсов, ручное обновление | Без запроса на каждое открытие; дата сохранения; предупреждение перед завершением обновления с потерей доступа |
| Buildin | Отдельный адаптер публичных страниц и нормализация блоков/ресурсов | Основная статья отделена от навигации сайта; связанные страницы подключаются явно |
| Читаемые URL | Slug, проверка уникальности, канонический адрес и исторические перенаправления | Внутренний ID стабилен; в пользовательских адресах нет GUID |
| Видео и аудио | Файловый плеер, Range, проверка кодеков, адаптеры ссылок | Rutube, YouTube, VK как целевые площадки; каждый вариант проверяется реально |
| Управление | Авторизация редактора, таблица материалов, метаданные, версии и видимость | Публичные изменяющие API WBook закрываются; без устройства LMS |
| Источники | Настройка разрешённых TechHelper origins, проверка соединения и возможностей конвертера | Без административных токенов TechHelper; регистрация видеопровайдеров остаётся задачей разработчика |
| Размещение | Выбрать репозиторий, сервер, БД и хранилище; адаптировать D1/R2-зависимости, резервировать и восстановить | Отдельный сервис; текущее размещение WBook не используется автоматически |
| Потребители | Пункт «Библиотека» в Академии, постоянные URL и API для приложения | Без создания учебных модулей и переноса LMS-админки |

Очередность: модель/доступ/оболочка → каталог и файлы → чтение и оформленные документы → PPTX и share → медиа → управление подборками и источниками → размещение и подключения. Внутри этапов возможна другая последовательность, но публичная запись без защиты не выпускается. Это состав будущей работы, а не начатая реализация.

## Правила проверки макетов

- Названия вкладок и действий должны соответствовать реальным возможностям выбранного материала.
- Визуальный PDF/слайд не исчезает из-за отсутствия текста. Недоступные режимы имеют объяснение.
- У share-статьи есть дата сохранения; обычное открытие не запрашивает источник. Закрытый оригинал не загружается. При отказе ручного обновления сохранённое содержимое остаётся видимым, пока редактор не завершит обновление с предупреждённой потерей доступа.
- У видео без опубликованного текста не появляется выдуманная расшифровка. Другие источники не маскируются под Rutube.
- У каждого вида просмотра есть возврат к библиотеке, название, доступные режимы и понятное происхождение.
- Слайды не обещают анимацию; Word не предлагает редактирование; библиотека не показывает оценки, уроки, назначения и сертификаты.
- Продолжение чтения в макетах подписано как сохранённое в этом браузере, без обещания синхронизации устройств.
- Управление отделено от чтения. Возможность скачивания локального оригинала определяется выбранной политикой и не переносится автоматически на share.
- Кириллица, контраст, обрезка содержимого и мобильная ширина проверяются на экспортированных изображениях. Статические кнопки не являются проверкой работающих функций.

## Границы и открытые решения

Нужно определить доступ к каталогу, способ входа редактора, целевое размещение, лимиты, доверенные TechHelper-серверы и подтвердить образцы документов/видеоссылок. Макеты не подменяют эти решения. Изображения не являются доказательством работоспособности импортёра, проигрывания видео, конвертации или интеграции с живыми источниками.

Не добавлены избранное, пользовательские рейтинги, социальные функции, совместное редактирование, OCR/транскрибация, автоматическое кодирование видео и синхронизация чтения между устройствами: пользователь их не запрашивал для первой версии.
