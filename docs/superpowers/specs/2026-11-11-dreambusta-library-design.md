## 1. Задача и выбранные границы

DreamBusta — независимая библиотека книг, документов, презентаций, видео и подкастов. Загружаем материал один раз либо подключаем его внешней ссылкой, включая шеринговые ссылки DreamAgent/TechHelper. Читалка, Академия и приложение используют одну запись библиотеки по постоянному адресу и через API.

Подтверждено пользователем:

- работать в E:\academy\sites\dreambusta на основе перенесённого WBook;
- использовать существующую читалку WBook;
- взять оформление и цветовую схему фронтенда E:\DA\DA\techhelper;
- предусмотреть отдельный репозиторий и независимый сервер;
- в Академии сделать отдельный пункт «Библиотека» с переходом к DreamBusta вне курсов;
- не переносить загрузку и просмотр HTML-уроков из ZIP;
- вместо этого подключать шеринговые ссылки DreamAgent/TechHelper с корректным отображением содержимого внутри DreamBusta;
- предоставить выбор между чтением текста, режимом WBook и просмотром исходного PDF;
- брать из Академии только необходимое: её устройство создавалось для другой задачи;
- принимать загружаемые Markdown, TXT, Word и электронные книги;
- поддерживать как видеофайлы, так и ссылки на видео из разных источников, без привязки библиотеки только к Rutube;
- добавить загрузку PPTX, используя подходящие механизмы презентаций TechHelper и DreamAgent Desktop;
- сохранять полученное опубликованное содержимое share-материалов, открывать его без повторной загрузки источника и обновлять по явному действию; предупреждать о возможной недоступности после обновления;
- подключать публичные страницы Buildin по шеринговой ссылке;
- делать пользовательские ссылки на материалы и подборки читаемыми, без GUID.

## 2. Что уже перенесено из WBook

В dreambusta скопированы 154 исходных файла из E:\WBook\app. Само приложение находится непосредственно в dreambusta, без дополнительной папки app над package.json. Исходная установка WBook сохранена.

Перенесены:

- React 19, TypeScript, Next/Vinext, Tailwind 4 и компоненты;
- каталог книг, поиск по названию и автору, загрузка выбором файла и перетаскиванием;
- полный текст и режим показа одного слова со скоростью, жестами и клавиатурой;
- сохранение места чтения и скорости в localStorage текущего браузера;
- импорт TXT, EPUB, FB2, FB2.ZIP, DOCX, PDF с текстовым слоем, MOBI/AZW3 без DRM;
- хранение оригинала и извлечённого текста, SHA-256 для одинаковых файлов;
- API книг, схема каталога, тесты импортёров и читалки;
- существующие привязки D1/R2, Wrangler и инструкции прежнего размещения WBook.

Не переносились node_modules, сборки, вложенный Git, секреты и личная библиотека .wrangler/state. Новая папка не содержит книг исходной установки.

Текущие ограничения: каталог рассчитан на книги; нет интеграции шеринговых ссылок и самостоятельной авторизации редактора; прогресс остаётся в одном браузере; PDF/DOCX превращаются в текст без исходной вёрстки. MD, старый DOC, PPTX и видео пока не входят в список импортируемых форматов WBook — их поддержка требует реализации. Текущий API требует непустой извлечённый текст и поэтому не является готовым загрузчиком PDF-сканов, презентаций без текста или медиа.

## 4. Общая схема

~~~text
DreamBusta — отдельный сервис
├── Каталог и подборки
├── Добавление
│   ├── Файл: книга / документ / презентация / видео / аудио
│   └── Ссылка: DreamAgent/TechHelper / видеосервис / прямой медиафайл
├── Просмотр и чтение
│   ├── Документ / PDF / слайды презентации
│   ├── Обычный текст
│   ├── Скорочтение WBook
│   └── Видео / аудио
└── API и постоянные адреса
    ├── Читалка
    ├── Академия → «Библиотека»
    └── Приложение
~~~

Локально загруженные материалы хранятся в DreamBusta. У подключённого по шеринговой ссылке материала исходником остаётся DreamAgent/TechHelper, а полученная опубликованная версия сохраняется для повторного чтения. Открытие сохранённой версии не перезапрашивает страницу источника. Потоковые медиа и не сохранённые ресурсы могут требовать сети; их наличие в карточке не обещает офлайн-воспроизведение.

Рекомендуем сохранить React WBook и добавить независимые адаптеры получения материалов и их представлений. Перенос всей Академии или всего TechHelper для этого не требуется. Рекомендация не является уже выбранным окончательным стеком сервера.

## 5. Выбор способа чтения

### 5.1. Пользовательский выбор

Для PDF показываем переключатель:

~~~text
[ PDF ]  [ Текст ]  [ Скорочтение ]
~~~

- **PDF** — страницы с исходной вёрсткой, изображениями, таблицами и формулами.
- **Текст** — удобное чтение извлечённого текста с переносом строк, размером шрифта и поиском.
- **Скорочтение** — существующий режим WBook с показом одного слова и управлением скоростью.

Для других текстовых материалов также доступны обычное чтение и WBook. Если источник предоставляет оформленное представление, добавляем режим «Документ» или «Статья». Пользователь не обязан читать документ только как PDF или только по одному слову.

Для Word/DOCX предлагаем аналогичный выбор: **Документ / Текст / Скорочтение**. В первом режиме используем существующий DOCX-просмотрщик TechHelper с оформлением, таблицами и изображениями, в двух других — текст для чтения. Это подключение имеющегося просмотрщика, а не разработка Office-редактора.

Предлагаемое начальное поведение: при наличии корректного текста открывать текстовый режим, затем запоминать последний выбор пользователя для материала. Это настройка интерфейса, а не автоматический переход при ошибке другого режима.

### 5.2. Реальные возможности определяют доступные режимы

| Материал | Режимы |
|---|---|
| Текстовая книга / TXT / импортируемые EPUB, FB2, MOBI, AZW3 | Текст, скорочтение |
| Загруженный MD / Markdown | Оформленная статья, текст без служебной разметки, скорочтение |
| PDF с доступным текстовым слоем | PDF, текст, скорочтение |
| PDF-скан без доступного текста | PDF; текстовые режимы недоступны с объяснением |
| Загруженный DOCX | Документ через просмотрщик TechHelper после его подключения; текст и скорочтение через импортёр WBook; исходный файл — по разрешению скачивания |
| Старый DOC | Преобразование в DOCX, затем документ, текст и скорочтение; оригинал сохраняется |
| PPTX | Слайды через подготовленный PDF; текст по слайдам и скорочтение при наличии извлекаемого текста |
| Расшаренный документ или статья БЗ | Оформленное опубликованное представление; текст и скорочтение, если текст доступен |
| Видео / аудио / запись встречи | Плеер; текст и скорочтение только при наличии опубликованной расшифровки |

«Всё читать» означает сделать текстовые режимы общими для материалов, у которых есть доступный текст. Это не обещание автоматически распознать скан, расшифровать любую запись или преобразовать бинарный файл.

В модели сохраняем доступные представления и их состояние: например PDF доступен, извлечение текста выполняется, текста нет или извлечение завершилось ошибкой. Отсутствие текста не делает готовый PDF ошибочным материалом. Скан можно добавить и открыть как PDF.

### 5.3. Сохранение позиции

Переключение режимов не создаёт дубликат документа и не сбрасывает место чтения. Для PDF текст желательно извлекать с привязкой к страницам и диапазонам текста, чтобы связывать позицию страницы с позицией чтения.

Текущий импортёр WBook сохраняет абзацы без карты страниц: соответствие PDF-страницы и слова нужно добавить. Если точного соответствия нет, сохраняются отдельные позиции режимов; пользователю не показывается выдуманная точная синхронизация. Позиция связана с версией текста, а не только с названием материала.

### 5.5. Просмотр Word/DOCX

В TechHelper найден не только импорт текста: frontend_docx_editor — отдельная React/Slate-библиотека @techhelper/docx-editor. Её экспорт DocxEditor принимает readOnly и умеет loadFromBuffer; Vue-обёртка DocxEditorWrapper.vue передаёт эти параметры, а PublicDocumentView.vue использует её для публичного чтения DOCX.

Для DreamBusta берём именно режим просмотра, отключая изменение, комментарии, историю редактирования и экспорт без разрешения. Оформленное представление и извлечённый текст относятся к одной доступной версии. Для шеринговой ссылки структурированное опубликованное содержимое имеет приоритет; закрытый оригинал не запрашивается для обхода ограничений источника.

Исходники: E:\DA\DA\techhelper\frontend_docx_editor\src\index.ts, src/components/DocxEditor.tsx и src/components/SlateEditor.tsx; frontend_shadcn/src/components/features/documents/DocxEditorWrapper.vue. В библиотеке объявлены peerDependencies React 18, а WBook использует React 19: совместимость нужно проверить при подключении. Точность отображения сложных документов проверяется на примерах; полное совпадение с Microsoft Word заранее не заявляется. Старый бинарный .doc не следует считать автоматически поддержанным DOCX-просмотрщиком: его подготовка описана ниже.

### 5.6. Загружаемые текстовые форматы и книги

MD и TXT — самостоятельные материалы, не только приложения к другим файлам. Все они проходят общий путь: добавить файл → получить текст и доступные представления → открыть подходящим способом. Пользователь выбирает чтение; ему не требуется вручную преобразовывать MD в TXT или DOC в DOCX.

| Формат | Требуемая обработка | Что уже имеется |
|---|---|---|
| MD, MARKDOWN | Оформленная статья с заголовками, списками, таблицами и ссылками; отдельный нормализованный текст для обычного чтения и WBook | В WBook импорт MD нужно добавить; Markdown-представления и рендеринг есть в TechHelper |
| TXT | Декодирование текста, абзацы, обычное чтение и WBook | Импортёр WBook уже имеется |
| DOCX | Сохранение оригинала, оформленный просмотр и извлечение текста | Извлечение — WBook, просмотр — библиотека TechHelper |
| DOC | Серверное преобразование в DOCX, далее тот же путь, что у DOCX | В TechHelper есть конвертация через LibreOffice; в DreamBusta её ещё нет |
| PDF | Оригинальный PDF и, при наличии текста, обычное чтение/WBook | Сочетание механизмов TechHelper и WBook |
| EPUB, FB2, FB2.ZIP, MOBI, AZW3 | Импорт текста и метаданных книги, обычное чтение/WBook | Существующие импортёры WBook, без поддержки DRM |

Оригинал остаётся неизменным; результаты преобразования сохраняются как представления этого же материала. Для DOC нужен установленный серверный конвертер: переименование расширения не является преобразованием. В TechHelper проверены backend/common/document_formats.py и services/document_file_conversion.py: для DOC целевой формат DOCX, преобразование выполняет LibreOffice. Берём только необходимый адаптер преобразования, а не всю систему редакторов и обработчиков файлов.

TXT должен корректно открывать распространённые кодировки, уже учитываемые WBook. MD рендерится с очисткой HTML; его служебные символы не попадают в поток скорочтения. Относительные изображения и вложения требуют доступной базы ресурсов: один файл MD не содержит автоматически файлы, на которые ссылается. При недоступном ресурсе текст остаётся читаемым, а проблема явно видна.

Форматы подключаются через расширяемый реестр импортёров. Фраза «другие книги» не означает обещание открыть любой неизвестный файл: неподдержанный формат получает понятное сообщение. Дополнительные форматы добавляются по реальным образцам, без пересмотра всей модели библиотеки.

### 5.7. Презентации PPTX

PPTX — самостоятельный материал библиотеки. Пользователь загружает исходную презентацию и получает выбор **Слайды / Текст / Скорочтение**. Для презентации по умолчанию открываются слайды; последний выбранный режим запоминается. В первой версии «Слайды» используют подготовленный PDF: перелистывание, миниатюры, масштаб и полный экран. Исходный PPTX сохраняется отдельно от PDF-представления и текста.

В TechHelper уже есть этот путь: backend/common/document_formats.py направляет семейство презентаций в PDF, а backend/common/services/document_file_conversion.py использует LibreOffice с фильтром impress_pdf_Export. Для DreamBusta адаптируем необходимый конвертер и подключаем PDF-просмотрщик. Отсутствие конвертера или ошибка подготовки отображаются явно; состояние подготовки слайдов отделяется от состояния извлечения текста. Слайды без текста остаются доступными для просмотра. Шеринговая презентация использует разрешённое источником представление по правилам раздела 6.

В DreamAgent Desktop найдена отдельная нативная реализация:

- E:\DA\DA\dreamagent-desktop\src\main\presentation-pptx\read.ts и index.ts — открытие PPTX, проверка пакета, порядок слайдов через связи presentation.xml, разбор текста, изображений и объектов;
- src/shared/presentation.ts — модель сцены, слайды, стили текста, изображения и предупреждения о неподдержанных объектах;
- src/renderer/src/components/presentation-editor/ — Vue-интерфейс с канвой и панелью слайдов, связанный с Electron API и @open-pencil/vue.

Парсер и модель подходят как основа отдельного извлечения текста и будущего нативного просмотра слайдов. Веб-интерфейс требует адаптации: в первой версии не переносим редактор, Electron-сессии и сохранение презентации. Текст группируется по реальному порядку слайдов с привязкой к их номерам; сортировка имён slide1.xml, slide2.xml не заменяет порядок презентации. Если такой извлекатель не подключён, можно использовать доступный текст PDF с привязкой к страницам; источник извлечения фиксируется, точное совпадение порядка блоков не заявляется без проверки. Заметки докладчика не добавляются автоматически к видимому тексту слайда.

Требование первой версии — PPTX. Старый PPT и ODP возможны через тот же конвертер после проверки образцов; их наличие в реестре TechHelper не доказывает работоспособность каждого файла. Просмотр PDF сохраняет статический вид слайдов, но не воспроизводит анимацию, переходы и встроенное видео. Полное совпадение с PowerPoint и редактирование не входят в первую версию.

### 5.8. Видео: файлы и ссылки разных источников

Два равноправных способа добавления: загрузить видеофайл либо вставить ссылку на видео. В карточке указываются название, обложка, описание и источник. Загруженное видео хранится в DreamBusta; внешняя ссылка остаётся связанной с площадкой и не означает автоматическое скачивание ролика.

| Источник | Как показываем |
|---|---|
| Загруженный видеофайл | Встроенный плеер, перемотка, громкость, полный экран; базовые целевые форматы MP4 и WebM с проверкой реальных кодеков браузера |
| Прямая ссылка на медиафайл | Тот же плеер, если источник разрешает воспроизведение и частичную загрузку; поддержка определяется ответом источника и кодеком, а не только расширением URL |
| Видеоплощадка: Rutube, YouTube, VK Видео и другие | Адаптер провайдера распознаёт ссылку на ролик, получает доступные метаданные и формирует разрешённое встраивание; каждый провайдер проверяется отдельно |
| Публичная запись DreamAgent/TechHelper | Разрешённый плеер и данные публичного API; расшифровка только если она опубликована |

Первую версию проектируем с несколькими провайдерами, а не с единственным полем Rutube. Начальные целевые площадки — Rutube, YouTube и VK Видео; конкретные варианты ссылок и возможность встраивания проверяются на реальных роликах при реализации. Новые источники подключаются через реестр адаптеров без изменения типа материала. Ссылки на канал или плейлист не выдаются за отдельное видео; выбор ролика нужен явно.

Для неизвестной площадки разрешается карточка внешней ссылки с кнопкой «Открыть у источника», но она явно отличается от встроенного просмотра. Если ролик удалён, закрыт либо площадка запретила встраивание, показываем причину и доступный переход к источнику. Произвольный HTML-код плеера администратору вставлять не требуется. Настройки автовоспроизведения и сохранение времени учитывают возможности плеера провайдера; точная синхронизация позиции для любого сервиса не обещается.

Неподдерживаемый браузером кодек не считается готовым к просмотру только потому, что файл загрузился; состояние показывается до публикации. Собственное перекодирование видео и универсальная поддержка потоковых форматов требуют отдельного решения. Текстовые режимы появляются только при доступных субтитрах или расшифровке; сама видеоссылка не создаёт текст.

## 6. Материалы по шеринговым ссылкам

### 6.1. Что поддерживает текущий код DreamAgent/TechHelper

| Ссылка во фронтенде источника | Содержимое |
|---|---|
| /shared/d/<uuid>-<название> | Каноническая публичная ссылка документа |
| /shared/<token> | Существующая токенная ссылка документа |
| /shared/kb/<token> | Статья БЗ; возможен параметр page_id для разрешённой подстатьи |
| /shared/s/<uuid>-<название> | Каноническая публичная ссылка записи |
| /shared/meetings/<token> | Существующая токенная ссылка записи |

Поддерживать старые и канонические формы, не привязывать идентичность документа к изменяемой части названия. Для канонической ссылки документ/запись определяется по GUID, а для статьи БЗ сохраняется контекст токена и page_id.

Подтверждённые исходники TechHelper:

- frontend_shadcn/src/router/index.ts — публичные маршруты;
- frontend_shadcn/src/lib/publicSharing.ts и backend/common/public_sharing.py — канонические и старые адреса;
- backend/api/urls.py — API /api/shared/..., включая file-content, file-access и file-source;
- backend/api/views.py — PublicDocumentShareViewSet и PublicPageShareViewSet;
- backend/api/document_file_actions.py — выдача только разрешённого опубликованного представления;
- frontend_shadcn/src/views/PublicDocumentView.vue и PublicKBArticleView.vue — форматы и публичное отображение;
- backend/meeting_voice/public.py — выдача публичной записи и её разрешённых ресурсов.

### 6.2. Добавление в библиотеку

1. Администратор вставляет шеринговую ссылку.
2. DreamBusta распознаёт поддерживаемый источник и проверяет доступ по этой ссылке.
3. Получает разрешённые название, тип, описание/превью и доступные представления; показывает предпросмотр.
4. DreamBusta сохраняет полученное опубликованное представление и разрешённые ресурсы с датой получения. Администратор при необходимости меняет подпись и обложку карточки и добавляет материал в подборку.
5. Пользователь открывает карточку внутри DreamBusta и выбирает доступный режим просмотра/чтения.

По уточнению пользователя базовый режим — связанный материал с сохранённой опубликованной версией. При обычном открытии показываем её и дату получения без повторного запроса к источнику. Кнопка «Обновить из источника» явно получает новое разрешённое содержимое. Сохранённая версия не называется актуальной без проверки, автоматического фонового обновления в первой версии нет. Для общего каталога обновление выполняет редактор; читатель видит дату сохранения и источник. Удалять общую сохранённую версию читатель не может.

### 6.3. Корректное отображение

Получаем содержимое через разрешённые публичные API источника и показываем своим интерфейсом. Не скачиваем произвольную HTML-страницу как документ и не считаем вставку URL в iframe универсальным решением: в production-настройках TechHelper есть X_FRAME_OPTIONS = DENY, а возможность встраивания конкретной страницы должна проверяться отдельно.

Для доступа браузера к другому домену нужен согласованный CORS либо адаптер DreamBusta на сервере. Рекомендуемый адаптер работает только с настроенными доверенными адресами TechHelper и публичными share-методами; не передаёт пользовательские cookies/административные токены и не становится универсальным прокси произвольных URL. Выданные источником файловые URL тоже проверяются, относительные пути разрешаются относительно источника.

Сохраняем структуру поддерживаемого представления: абзацы, заголовки, списки, таблицы, изображения и ссылки. Для TipTap/Slate используется явное преобразование в поддерживаемый формат; неизвестные блоки не исчезают молча. При неподдерживаемом представлении даём понятное сообщение и переход к источнику.

У БЗ переход к подстатье идёт в том же публичном контексте, якоря остаются внутри статьи, а закрытые родительские/соседние материалы не подгружаются. При получении файла учитываем file_info и API доступа, а не делаем предположение по расширению URL.

### 6.4. Сохранённая версия и ручное обновление

- Обычное открытие показывает сохранённую опубликованную версию, даже если источник позднее изменил или закрыл ссылку. Не выполняем проверку доступа перед каждым открытием и не очищаем материал в фоне.
- Всегда показываем дату сохранения и пометку «Сохранённая версия». До ручного обновления источник мог измениться; предупреждение формулируется как «При обновлении материал может стать недоступен». Без проверки не утверждаем, что ссылка уже отозвана.
- Если при ручном обновлении выяснилось, что доступ закрыт, старая версия остаётся видимой с предупреждением «Источник недоступен. Если завершить обновление, сохранённое содержимое станет недоступно». Редактор может оставить версию либо явно завершить обновление с потерей доступа. Только во втором случае дальнейшая выдача этой сохранённой версии прекращается; карточка и её постоянный ID остаются. Это предложенное уточнение интерфейса к пожеланию пользователя о предупреждении перед обновлением.
- Ошибка сети или timeout не удаляет последнюю успешно сохранённую публикацию. При успешном обновлении содержимое и дата меняются вместе, а позиции чтения учитывают новую версию.
- Текстовый режим не расширяет права по сравнению с опубликованным представлением. Публичное чтение не означает разрешение скачать оригинал.
- Публичный файловый API TechHelper ограничивает доступ текущей опубликованной версией и запрещает variant=original. Нельзя обращаться к закрытому оригиналу ради извлечения текста.
- Текст и PDF должны соответствовать одной доступной версии. В TechHelper оригинальный PDF не выдаётся как preview отредактированной текстовой версии, если он больше не соответствует опубликованному содержимому. DreamBusta сохраняет это различие.
- Параметры приватных ссылок и share-токены не выводятся в аналитике и публичных метаданных карточки; работоспособный адрес хранится только там, где необходим для разрешённой выдачи.
- Для чтения доступна сохранённая версия; ручная проверка источника и его результат показаны отдельно. Несохранённый ресурс не подменяется закрытым оригиналом.

Для записей отображаем аудио/видео и расшифровку только в том объёме, который возвращает публичный API. Наличие записи не означает наличие общедоступной расшифровки.

### 6.5. Публичные страницы Buildin

Пользователь добавил источник Buildin и привёл [публичный пример](https://buildin.ai/share/480fea3b-bf25-478c-8c33-111c002defdc). 11 ноября 2026 страница открылась без входа; получены основной заголовок Buildin Developer Guide, разделы, ссылки на руководства и документацию. В выдачу также попала большая навигация сайта: она не должна автоматически становиться содержимым импортированной статьи. Временные подписанные адреса ресурсов не используются как постоянные публичные адреса библиотеки.

Buildin подключается отдельным адаптером в общем реестре share-источников. По ссылке определяем страницу, получаем разрешённые заголовок, основное содержимое и ресурсы, показываем предпросмотр и сохраняем публикацию с датой. Действует то же ручное обновление из раздела 6.4. GUID исходной ссылки остаётся внутренним идентификатором источника; пользовательская ссылка DreamBusta получает читаемый slug.

Требуется сохранять поддерживаемые заголовки, абзацы, списки, таблицы, цитаты, код, изображения и ссылки. Связанные страницы подключаются отдельно или по явному выбору редактора; импорт всего пространства, приватных соседних страниц и навигации сайта не выполняется автоматически. Неизвестные интерактивные блоки, базы и встраивания явно отмечаются и получают переход к источнику, а не исчезают молча. Текст и скорочтение доступны по извлечённому тексту основной сохранённой страницы.

Наличие V2 API в документации Buildin не подтверждает анонимную выдачу произвольного share-содержимого через этот API. Конкретный способ получения опубликованной страницы предстоит проверить при реализации; просмотр одного примера не является проверкой всех блоков и вложений. Встраивание всей страницы в iframe не считается универсальной реализацией.

## 7. Каталог, управление и данные

Материал имеет постоянный materialId, название, описание, автора/источник, обложку, тип (книга, документ, презентация, видео, аудио), теги и принадлежность к подборкам. Способ получения хранится отдельно: загруженный файл, share-ссылка с провайдером DreamAgent/TechHelper или Buildin, прямой медиаадрес либо видеоссылка с указанием провайдера. Rutube — один из провайдеров, а не отдельный тип материала.

- Для загруженного файла сохраняем оригинал и производные представления; SHA-256 помогает не хранить одинаковые файлы повторно.
- Для связанного материала сохраняем нормализованную идентичность источника, рабочую share-ссылку, полученную опубликованную версию, дату сохранения и результат последнего ручного обновления. Редактирование названия в источнике не создаёт новую запись.
- Для видеоплощадки сохраняем провайдера и ID ролика отдельно от исходного URL; разные поддерживаемые ссылки на тот же ролик распознаются как один источник. Для временного прямого медиаадреса не выдумываем постоянную идентичность.
- Стабильный ID карточки не зависит от хеша нового файла или нового названия.
- Подборки содержат ссылки на материалы с порядком; один материал может входить в несколько подборок.
- Удаление из подборки удаляет связь, а не общий материал.
- Поиск первой версии работает по разрешённым метаданным, без обещания индексировать содержимое всех файлов.
- Администратор может добавлять файл/ссылку, редактировать карточку, загружать обложку, менять порядок и скрывать материал. Управление требует авторизации; открытые операции текущего WBook не сохраняются как политика нового сервиса.
- Отдельный конструктор курсов, сложная система ролей, встроенный редактор документов и LMS-публикация для первой версии не нужны.

Для локальных материалов обновление файла создаёт новую версию, сохраняя materialId. Для share-ссылки сохраняем полученную публикацию; ручное обновление запрашивает текущую доступную версию источника. Запрос произвольной исторической версии у источника не обещается.

Архивирование карточки скрывает её из общего каталога. Изменение доступа у источника само по себе не запускает удаление сохранённой публикации: её обновление и предупреждения описаны в разделе 6.4. Доступ к локально сохранённому материалу определяется политикой DreamBusta. Техническая политика хранения старых версий определяется отдельно от LMS.

### 7.1. Читаемые постоянные ссылки

Публичный адрес материала — например /library/reglament-soglasovaniya, подборки — /collections/start-v-dreamdocs. GUID, хеш файла и технический ID не добавляются к пользовательскому адресу. Предлагается латинская транслитерация названия с дефисами; редактор может изменить slug до сохранения. Это предложение для макетов, а не уже работающий роутер.

Slug отделён от стабильного внутреннего ID и от URL источника. Совпадающие названия получают понятный порядковый суффикс (-2, -3); занятые, зарезервированные и исторические адреса не назначаются другой записи. Переименование заголовка не меняет адрес автоматически. При явной смене slug старый адрес сохраняется как перенаправление на текущий. Скопировать ссылку из любого просмотрщика означает скопировать актуальный канонический адрес; потребители API по-прежнему могут хранить внутренний materialId.

В текущем TechHelper есть slug-маршруты рабочих пространств/проектов, но изученный публичный share-генератор использует GUID с названием. Для DreamBusta выполняем более строгую просьбу пользователя о ссылках без GUID, не копируя эту часть share-формата. Читаемый адрес не заменяет проверку прав: при закрытом каталоге доступ к материалу и представлениям проверяется независимо от slug. Формат чужих исходных share-ссылок DreamBusta не меняет.

## 8. API, файлы и независимое размещение

Отдельный сервис предоставляет HTTP API каталога, карточек, подборок и доступных представлений. Административные операции защищены отдельно. Потребители сохраняют materialId и постоянный адрес, а не временную ссылку хранилища.

Текущий WBook напрямую использует cloudflare:workers, env.DB и env.BUCKET. Для обычного VPS-размещения нужен слой доступа к каталогу/файлам и адаптация API; одного переименования конфигурации недостаточно. Конкретные HTTP-фреймворк, СУБД и поставщик хранилища пока не согласованы.

Требования к файлам:

- оригиналы и библиотека находятся вне каталога сборки, переживают обновление и резервируются вместе с каталогом;
- лимиты задаются по типу; текущие 25 МиБ WBook не распространяются автоматически на видео и подкасты;
- большое медиа не загружается полностью в память API-процесса; применяется прямая загрузка в хранилище с проверкой завершения;
- видео/аудио и PDF выдаются с подходящими MIME, поддержкой Range там, где нужна частичная загрузка;
- при закрытом доступе одинаковые права действуют на каталог, текст, PDF, плеер и файловые URL;
- старые API книг и адреса #read/<sha256> учитываются через совместимость или явную карту переноса, включая ключи локального прогресса.

Выбор открытой библиотеки или доступа после входа остаётся нерешённым. Share-ссылка из TechHelper не делает сам каталог DreamBusta автоматически публичным. Общий вход с продуктами, если он потребуется, проектируется отдельно; база пользователей и секреты Академии/TechHelper не копируются.

Сейчас dreambusta — папка репозитория sites, а не отдельный Git-репозиторий. Старые deploy/ и .openai/hosting.json относятся к WBook и не являются готовой конфигурацией нового размещения. Личная библиотека исходного WBook автоматически на сервер не переносится.

## 9. Роль Академии

Первый и необходимый шаг: пункт «Библиотека» в настольном и мобильном меню, URL из конфигурации, переход на каталог или подборку DreamBusta. Это веб-адрес, а не ссылка на локальную папку Windows.

Просмотр не требует создания модуля, не назначает курс и не изменяет результаты обучения. При недоступной библиотеке остальные страницы Академии продолжают работать.

Прямое использование материала внутри курса возможно позднее, если появится такая задача. Сейчас выбор версий для курса, импорт программ и перенос их админки не входят в обязательную реализацию.

В прежнем комплекте Академии есть 19 HTML ZIP, 12 Rutube-ссылок и 13 Markdown-статей. Их структура и 32 контрольные суммы были проверены в предыдущей редакции требований. Это исторический инвентарь, а не задание на перенос: HTML ZIP исключён пользователем, автоматическая миграция материалов Академии не запланирована. Конкретные нужные видео/статьи можно добавить отдельно выбранными поддерживаемыми способами.

## 11. Порядок работы

1. Сохранить рабочие импортёры и читалку WBook; ввести общую запись материала и авторизованное управление без зависимостей от LMS.
2. Добавить MD, подготовку старого DOC и PPTX; реализовать выбор PDF, документа, статьи либо слайдов / Текст / Скорочтение. Использовать просмотрщики и конвертер TechHelper, извлечение текста WBook и подходящие части PPTX-парсера Desktop.
3. Подключить share-адаптер документов и БЗ; сохранение опубликованной версии, структуру и ресурсы, ручное обновление, дату получения и предупреждение при потере доступа. Затем подключить публичные записи.
4. Добавить файловое видео/аудио, прямые медиаадреса и реестр видеопровайдеров с проверенными вариантами Rutube, YouTube и VK Видео; не создавать собственный сервис транскрибации.
5. Подготовить независимые репозиторий/сервер и проверяемое восстановление библиотеки.
6. Добавить ссылку в Академию и подключение каталога из приложения.

Это очередность результата, а не утверждённый план реализации по файлам. Отдельные репозиторий и сервер считаются готовыми только после фактического создания и проверки.

## 12. Приёмка

- Один материал открывается из каталога и другого продукта по тому же ID без повторной загрузки.
- Для PDF с текстовым слоем пользователь выбирает PDF, текст или WBook; после переключения документ и доступная версия остаются теми же.
- Для DOCX доступны оформленный просмотр, текст и WBook; в режиме просмотра документ нельзя изменить, а недоступный исходник не подменяется другой версией.
- PDF-скан открывается как PDF, отсутствие текста не вызывает ложное сообщение о повреждённом файле.
- Пользователь может читать текст книги, документа и статьи обычным способом или в WBook; медиа предлагает чтение только при доступной расшифровке.
- Повторное добавление той же share-ссылки или файла не создаёт необъяснимых дублей.
- Шеринговые документы/БЗ отображают поддерживаемые таблицы, списки, изображения, ссылки и подстатьи; переименование не ломает идентичность.
- Share-материал открывается из сохранённой публикации без повторного запроса к источнику; дата и предупреждение видны. Отказ при ручном обновлении не стирает содержимое молча: редактор оставляет версию либо явно завершает обновление с потерей доступа. Закрытый оригинал никогда не запрашивается.
- Публичная страница Buildin добавляется как отдельный share-источник; содержимое отделено от навигации сайта, связанные страницы не импортируются автоматически.
- Пользовательские адреса материалов и подборок читаемые и не содержат GUID; явная смена slug сохраняет работу старого адреса через перенаправление.
- Несоответствующий опубликованной версии исходный PDF не показывается как текущий документ.
- Локальный прогресс WBook, жесты, клавиатура и мобильное чтение продолжают работать; между режимами сохраняются корректные позиции.
- Только администратор меняет библиотеку; закрытые материалы не открываются обходным файловым URL.
- MD открывается как оформленная статья и как текст для чтения/WBook; TXT сохраняет абзацы и корректную кодировку.
- Старый DOC проходит реальное преобразование; недоступность или ошибка конвертера показывается явно, а исходный файл сохраняется.
- PPTX открывается как слайды; доступны миниатюры, масштаб и полный экран. При доступном тексте работают чтение и WBook с сохранением порядка слайдов; презентация без текста остаётся доступной визуально. Оригинал не подменяется PDF.
- Поддерживаемые видеофайлы, прямые медиаадреса и проверенные ссылки нескольких видеоплощадок воспроизводятся; нельзя считать проверку только Rutube достаточной. Удалённый ролик, запрет встраивания и неподдержанный кодек имеют явное состояние; внешняя карточка не выдаётся за работающий встроенный плеер.
- Библиотека переживает обновление и восстановление из резервной копии; недоступность внешнего источника не ломает каталог целиком.
- Пункт библиотеки в Академии работает на компьютере и телефоне без зависимости от курсов.
- Обработчика/просмотрщика HTML-уроков из ZIP в объёме работ нет.

## 13. Открытые решения и пределы исследования

Нужно определить: публичный либо закрытый каталог, целевые репозиторий/домен/сервер/хранилище, доверенные адреса TechHelper и допустимые размеры файлов. Примеры реальных шеринговых ссылок TechHelper нужны для будущей интеграционной проверки; живые материалы TechHelper в этой работе не запрашивались и в библиотеку не переносились. Присланный публичный пример Buildin отдельно прочитан для проектирования адаптера, как описано в разделе 6.5; работающая интеграция не создана.

Текстовый режим, серверное подключение share-ссылок, подготовка PPTX и адаптеры видеоплощадок — требования, а не уже готовая интеграция. Приложения и конвертер в этой работе не запускались; выводы об API TechHelper и просмотрщиках получены из локальных исходников. Проверка публичного примера Buildin не является интеграционным тестом. Функциональные тесты приложений, линтеры и сборки не запускались: меняются документы и отдельные статические макеты. Рендер макетов и их галерея проверяются отдельно.

Полнотекстовый поиск по всем файлам, собственные OCR/транскрибация, Office-редактирование, адаптивное видеокодирование и синхронизация прогресса между устройствами не включены в первую версию. Готовые разрешённые текст и расшифровка источника могут использоваться без переноса этих сервисов.
