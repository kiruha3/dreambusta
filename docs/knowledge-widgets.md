# База знаний и внешние помощники

## Контент и меню

Кабинет редактора: `/admin`. Здесь находятся загрузка материалов, карточки,
подборки, источники, настройки библиотеки и внешние помощники.

`/knowledge` показывает статьи и сохранённые публикации. В карточке любого
материала редактор может включить или выключить «Включить в базу знаний».
Для прежних статей и публикаций этот признак включён по умолчанию; файлы
библиотеки при обновлении приложения не переписываются.

В `/admin/settings` выберите материалы для быстрого доступа и задайте порядок
стрелками. Гости видят только открытые готовые материалы. Скрытые выбранные
материалы видит редактор. Закрытие библиотеки запрещает гостевой доступ
и работу внешних помощников.

Переход из подборки сохраняет её в адресе материала и хлебных крошках.
Недоступная подборка или материал вне неё не создают ложный путь.

## Создание помощника

1. Откройте `/admin/widgets` и нажмите «Создать помощника».
2. Укажите внутреннее название, заголовок, приветствие и цвет.
3. Добавьте разрешённые сайты, каждый в отдельной строке:
   `https://example.ru`. Это origin без пути и завершающего слеша;
   поддомены перечисляются отдельно. Звёздочки не поддерживаются.
   Для локальной проверки допустим `http://localhost:порт`.
4. Выберите материалы для ответов. Пустой список означает все открытые
   материалы. Флаг «База знаний» организует каталог; область помощника
   определяется собственным выбором материалов.
5. Нажмите «Опубликовать». Проверьте сохранённые настройки в предпросмотре.
6. Выберите плавающую кнопку или блок внутри страницы и скопируйте код.
   Разместите его в HTML разрешённого сайта. Для блока оставьте элемент
   с указанным `id` перед скриптом. Нескольким блокам нужны разные `id`
   и соответствующие `data-target`.

Код содержит адрес текущей Дримбусты. Код с localhost работает только на этом
компьютере. Для внешнего сайта откройте кабинет по HTTPS-адресу развёрнутой
Дримбусты и скопируйте код оттуда. Модель и индекс остаются в Дримбусте,
подключение API или учётной записи Теххелпера не требуется.

«Приостановить», удаление виджета, закрытие библиотеки или скрытие материала
отзывают доступ. Ответ повторно проверяет доступность источников перед выдачей.
Изменение настроек обновляет ревизию; если уже открытое окно сообщило об
истёкшей сессии, повторите вопрос. Секреты модели и сессия редактора не входят
в код вставки и не используются публичным окном.

## Локальные модели

В кабинете редактора откройте «Локальные модели» (`/admin/ai`). При установке
в подпапке адрес будет `/library/admin/ai`.

1. Проверьте статус Ollama. Её службу один раз устанавливает администратор
   сервера; после этого она стартует автоматически с systemd.
2. Скачайте `embeddinggemma:latest` для смыслового поиска и `gemma4:e2b` для
   ответов либо выберите другие совместимые модели по ресурсам сервера.
   Во время загрузки отображается прогресс, доступна отмена.
3. Выберите установленные модели в двух списках и сохраните настройки.
   При смене модели поиска индекс перестраивается в фоне. Поиск по словам
   остаётся доступен.
4. В блоке «В памяти» можно выгрузить модель из RAM. Следующий запрос или
   фоновая индексация могут загрузить её снова. Запросы приложения задают
   освобождение памяти после двух минут простоя.

Выбор сохраняется в базе и действует без перезапуска DreamBusta. Переменная
сервера `DREAMBUSTA_AI=off` принудительно запрещает AI; для включения через
интерфейс администратору нужно убрать её и перезапустить приложение.
Модели, выбранные для поиска или ответов, защищены от удаления из интерфейса.
Статус и операции доступны только редактору; изменение требует CSRF-сессию.
Произвольные URL, команды ОС и запуск systemd из веб-интерфейса не принимаются.

## Сервер

Поставляемый `deploy/dreambusta/nginx.conf` направляет `/api/`, `/embed.js`,
`/embed/` и `/embed-assets/` в API на 5276. В существующей установке примените
обновлённый vhost обычным процессом развёртывания из `operations.md` и проверьте
`nginx -t` перед reload. Не направляйте `/embed/*` в Vue fallback.
Архив релиза включает `server/widget-assets/`; приватный `data/` в него не входит.
Vite dev/preview проксируют эти пути автоматически.

Лимиты: 12 ответов и 30 подключений в минуту на посетителя; максимум 2 ответа
посетителя, 2 на виджет и 6 одновременно на сервис. Nginx должен перезаписывать
`X-DreamBusta-Client` фактическим адресом клиента, как в поставляемом конфиге.
API принимает этот заголовок только от локального прокси.

Диагностика:

- окно не загружается: опубликован ли виджет, открыта ли библиотека, правильно
  ли проксируется `/embed/`, разрешён ли точный origin сайта;
- вопрос недоступен: скрипт должен работать на странице родителя, не только
  голый iframe; проверьте `data-widget` и сообщения CSP в консоли;
- нет ответа: проверьте Ollama, модели и наличие текста у выбранных материалов;
- нет источника: скрытые, удалённые и ещё обрабатываемые материалы не участвуют;
- удалённый скрипт блокируется сайтом: добавьте адрес Дримбусты в `script-src`
  и `frame-src` CSP сайта, на котором размещается помощник.

## Проверки

`npm run test:e2e` проверяет основное приложение, поиск, чтение, кабинет
и виджет с отдельного origin. Все эти сценарии создают временные библиотеки;
рабочие материалы и пользователей не меняют.

## Чтение

В «Статье» и «Тексте» колесо прокручивает содержимое внутри области чтения.
Поиск и управление остаются над текстом. В WBook доступны скорость, управление
проигрыванием и ползунок слов; в обычном тексте остаётся компактная панель.
Индикатор «Позиция в статье» — процент внутренней прокрутки текущей страницы,
а не оценка прочтения. Позиции разных страниц сохраняются отдельно.
Оглавление можно скрыть или изменить его ширину разделителем; доступны
перетаскивание, стрелки клавиатуры, Home/End. Ширина сохраняется в браузере.
